web-module-graph Compiled import map (CLI)

Compile routing to an import map

The CLI asks a router once, ahead of time, and writes a standard import map and a lockfile in mport's format. The files on this page were produced by web-module-graph build from cli/modules.config.js: a basicRouter for HTML-module aliases (one of them depends on the scope), chained with fromMport(createRouter(...)) for packages (ranges resolved through an offline registry, a "down" mirror skipped by a file-system probe). The test suite checks they are up to date.

Commands

# from the package root
node bin/web-module-graph.js build --config examples/cli/modules.config.js \
  --out examples/cli/importmap.json --lock examples/cli/modules.lock.json
node bin/web-module-graph.js build --config examples/cli/modules.config.js --html --out examples/cli/importmap.html
node bin/web-module-graph.js resolve @tokens greet@^1 jsr:@demo/scoped@^2 @lib/ --config examples/cli/modules.config.js

The config's default export is a function, ({ lock }) => config. When the --lock file already exists the CLI passes it in, and the config hands it to mport (createRouter(routes, { lock })), so a rebuild pins the same versions and builds without asking the registry. --relock ignores it. When the router is a plain mport router, the CLI calls mport's own router.build(); for a chain like this one it uses compileImportMap() with mport's compileImportMap and mergeImportMaps.

Using the compiled map at runtime

      
Two loaders consume the same compiled map: one with importMap, one with router: importMapRouter(map). Both reproduce the build-time decisions without re-running the router. Package keys have no version: greet@^1 compiled to greet.
