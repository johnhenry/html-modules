Namespaces and the -- delimiter

<html-import src="./ui.html" as="ui"> is the HTML counterpart of import * as ui from "./ui.js". The as attribute names a namespace, not a single element: each export card, button, … is registered as <ui--card>, <ui--button>, … The module's author chooses the export names; the importer chooses the namespace.

One module, two namespaces

<script type="importmap">{ "imports": { "@demo/ui": "./components/ui.html" } }</script>

<html-import src="@demo/ui" as="shop"></html-import>              <!-- bare specifier, via the import map -->
<html-import src="./components/ui.html" as="admin"></html-import>
<shop--card>Registered by the shop import.shop--badge
<admin--card>Registered by the admin import.admin--badge

    Why --?

    A registered tag must be a valid custom element name, or the browser's native upgrade (which lets elements appear before their definitions) is lost. The table below asks this browser's customElements.define() about each candidate delimiter, for a one-word export (card) and a two-word export (custom-card).

    . reads well and is even legal inside a name, but ui.card has no hyphen, so one-word exports could never be registered. A single - is always legal but ambiguous: is ui-custom-card the custom-card export of ui, or the card export of ui-custom? Unicode separators such as · are legal but hard to type and easy to misread. -- always supplies the required hyphen, and because namespaces and export names are lower-case words joined by single hyphens, neither can contain --: every tag splits exactly one way. It also echoes CSS custom properties (--ui-accent).
