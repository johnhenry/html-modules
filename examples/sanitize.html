Sanitizing templates

A module URL is as trusted as a <script src>: its templates are stamped as real DOM, so <img onerror>, a javascript: link or an <iframe srcdoc> in one runs. sanitize is an opt-in function that every component template passes through at load time, before anything is registered. The module in components/untrusted.html carries all of those; each payload records itself in window.__pwned, and none of them runs below.

A function you write

createHTMLModules({ sanitize }) or HTMLModules.import(src, { sanitize }). The function receives the template's HTML and { def, url, window, report } and returns a string, a TrustedHTML or a DocumentFragment (stamped without being parsed again). Here, a small allowlist walk over a fragment: no scripts, frames, handlers or javascript: URLs.

    Async, per import, and what it reports

    The module is sanitized when it loads, so an async sanitizer works: nothing is registered until every template is done. A sanitizer may report() what it removed: it arrives as a sanitize event (onEvent) and as html-modules:sanitize on the document. A module is cached per sanitizer, so the same URL can be imported both ways under different tags.

      A sanitized module cannot import JavaScript

      A sanitizer vets templates; import() would run the file with the page's authority. So the HTML modules a sanitized module imports are sanitized too, and a .js one is an error.

        With @johnhenry/safe-fragment

        safeFragmentSanitizer({ profile }) from @johnhenry/html-modules/safe-fragment: sanitizeToFragment() under a versioned profile (here ui-v1 plus <slot>, part and ui--* elements, derived by registerTemplateProfile()). safe-fragment is a peer you pass in, not a dependency; this page loads a bundle of the pinned commit (npm run vendor:safe-fragment).
