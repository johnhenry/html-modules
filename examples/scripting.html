Scripting and lifecycle

Everything here is driven from script and checked live: creating an <html-import> and setting its properties, un-adopting a stylesheet, evicting a module from the cache, server-rendered (declarative) shadow DOM, a self-closed <html-binding />, a lazy import with nothing to wait for, and the security options (integrity, credentials, mode, a Trusted Types policy).

A scripted <html-import>

createElement, append, then set src and as: the import starts after the script, so both are seen. Changing src after it started is an error event, not a silent no-op.

    Un-adopting and unloading

    Removing an adopt binding gives its stylesheet back; HTMLModules.unload(src) evicts the cache entry so the next load fetches again (tags stay registered).

      Server-rendered shadow DOM

      renderDeclarative(def, innerHTML) produces <template shadowrootmode> markup. The browser's parser builds the shadow roots (open and closed); upgrading keeps their content and still applies the component's styles.

        Markup mistakes that used to be silent

        <html-binding export="card" /> does not close the element in HTML, so the next binding became its child and was dropped. Now it is an error event; so is a lazy import with no tag to wait for.

          Security options

          integrity is checked with SubtleCrypto against the fetched bytes; credentials and mode reach fetch(); a trustedTypes policy wraps the HTML the library parses.
