html-modules Bindings

Selective imports and custom tag names

Custom element names are global and permanent: a namespace import registers every component of a module for the life of the page. <html-binding> children narrow an import to the exports the page actually uses, choose tag names, adopt stylesheets and expose data. This goes beyond the PRD, which specifies only the whole-namespace form; element= is the markup form of the PRD's definition.define(tag).

Only what the page uses

<html-import src="./components/ui.html" as="pick">
  <html-binding export="card"></html-binding>                          <!-- <pick--card> -->
  <html-binding export="button" element="buy-button"></html-binding>   <!-- a tag of your choosing -->
  <html-binding export="button" element="save-button"></html-binding>  <!-- the same export, a second tag -->
  <html-binding export="default" element="tip-box"></html-binding>    <!-- the default export -->
  <html-binding export="meta"></html-binding>                          <!-- data: el.bindings.meta -->
</html-import>
<html-import src="./components/themes.html">
  <html-binding export="ocean" adopt></html-binding>                   <!-- a stylesheet, adopted by the page -->
</html-import>

Load only

      
An import with no as and no bindings loads the module (for its side effects, or to warm the cache) and registers nothing.
