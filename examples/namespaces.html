html-modules Namespaces

Namespaces and delimiters

<html-import src="./ui.html" as="ui"> is the HTML counterpart of import * as ui from "./ui.js". The as attribute names a namespace, not a single element: each export card, button, … is registered as <ui--card>, <ui--button>, … The module's author chooses the export names; the importer chooses the namespace, and, if it wants something other than --, the delimiter.

One module, two namespaces

<script type="importmap">{ "imports": { "@demo/ui": "./components/ui.html" } }</script>

<html-import src="@demo/ui" as="shop"></html-import>              <!-- bare specifier, via the import map -->
<html-import src="./components/ui.html" as="admin"></html-import>
<shop--card>Registered by the shop import.shop--badge
<admin--card>Registered by the admin import.admin--badge

    Choosing a delimiter

    delimiter changes what goes between the namespace and the export name. The same module is imported three times below: with the default --, and twice with -. A page can change the default for all of its imports with createHTMLModules({ delimiter: '-' }); a delimiter attribute (or the delimiter option of HTMLModules.import() and bind()) overrides it. 

    <html-import src="./components/ui.html" as="ui"></html-import>                        <!-- <ui--card> -->
<html-import src="./components/ui.html" as="ui" delimiter="-"></html-import>          <!-- <ui-card> -->
<html-import src="./components/ui.html" as="ui-kit" delimiter="-"></html-import>      <!-- <ui-kit-card> -->
    <ui--card>the default, -- <ui-card>delimiter="-" <ui-kit-card>as="ui-kit" delimiter="-"

    What each import registered: el.tags

    <ui-kit-card> could be the card export of ui-kit or the kit-card export of ui. The runtime never parses a tag to find out: each binding records { tag, namespace, export } when it is made, and el.tags exposes the records.

      Inside a module

      A module's own imports can choose a delimiter too. tally.html imports the icons as as="ic" delimiter="-" and uses <ic-check> in its template. A module's imports use -- unless they say otherwise, whatever this page's default is, so a module's templates always know their tags.

        Why -- is the default
        
      
        
        A registered tag must be a valid custom element name, or the browser's native upgrade (which lets elements appear before their
        definitions) is lost. The table below asks this browser's customElements.define() about each candidate delimiter,
        for a one-word export (card) and a two-word export (custom-card).
      
        
      
        
      
        
        -- cannot appear inside a namespace or an export name (they are lower-case words joined by single hyphens), so every
        tag splits exactly one way, and it always supplies the hyphen a custom element name needs, so one-word exports stay valid. It also echoes
        CSS custom properties (--ui-accent).
        - is compact and always valid, but ambiguous (ui-custom-card); that is fine when you control the names.
        . reads well and is legal inside a name, but ui.card has no hyphen, so one-word exports become invalid:
